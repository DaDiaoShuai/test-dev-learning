## 练习 1：locator.within() —— 在范围里找元素

文件：`01_within.py`，运行：`python 01_within.py`

页面上有大量同名元素时（每张商品卡都有一个「加入购物车」、每一行都有同名单元格），老办法是先定位父级再层层往里找。`within()` 把它写成人说话的顺序——`按钮.within(卡片)`，读作「卡片里面的那个按钮」。更重要的是：`nth()` 这类相对定位在它里面是「在每个父级里分别数」的，所以能一把抓出「每一行的第 3 个单元格」也就是整列。练习内置了一个本地页面（3 张商品卡 + 一张订单表），不访问任何网站。

验收标准：

- [ ] 运行后 4 条 PASS 全部打印，最后一行是「练习 1 全部通过」
- [ ] 能说清：为什么只按按钮名字找会匹配到 3 个、为什么 `nth(2)` 加不加 `within(行)` 结果完全不同

## 练习 2：--shuffle —— 把执行顺序打乱，抓顺序依赖

目录：`02_shuffle/`，运行：`npx playwright test` / `npx playwright test --shuffle`

有些用例自己不独立，靠前一条留下的数据才过（比如「取消订单」要靠「创建订单」先跑）。平时按固定顺序跑发现不了，`--shuffle` 把顺序随机打乱，这种用例立刻现形；打乱时终端会打印一个 seed（种子数），把 seed 原样传回去（`npx playwright test --shuffle 42`）就能复现同一顺序。目录里有 3 个文件共 6 条互相独立的用例，配好了验证用的配置。

两个容易踩的点，练的时候留意：

- 它永远会打乱**文件之间**的顺序；**文件内部**的用例只有在并行模式（`fullyParallel`）下才打乱，必须串行的组会保序——所以只开文件级打乱，同文件里的依赖还是藏得住
- seed 参数会「吞」紧跟其后的文件名：想只跑某个文件，别把文件路径直接写在 `--shuffle` 后面

验收标准：

- [ ] 不带参数跑：顺序是 A 到 F，6 条全过
- [ ] `--shuffle 42` 跑两次：两次顺序一模一样，且和默认顺序不同，6 条全过；换个 seed 顺序还会变
- [ ] 动手改坏一次：让某条用例去读另一条设置的共享变量，用 --shuffle 把它跑失败，再改回「每条自己造数据」的写法并恢复全过

## 练习 3：APIRequestContext 的 cookie 管理 —— 接口侧预置登录态

文件：`03_api_cookies.py`，运行：`python 03_api_cookies.py`

以前增删查 cookie 只有浏览器上下文有，接口测试想预置一个登录 cookie 只能绕道存储状态文件或手拼请求头。1.64 给接口请求上下文补齐了同一套方法：`add_cookies()` 预置、`cookies(url)` 查询、`clear_cookies()` 清除（可以按名字只清一条，不传参清全部）。练习用 httpbin 的 cookie 回显接口当靶子，全程不开浏览器。

验收标准：

- [ ] 运行后 4 条 PASS 全部打印，最后一行是「练习 3 全部通过」
- [ ] 能说清：按名字清和清全部的区别；预置 cookie 后为什么不用再手动拼请求头

## 附带说明：WebMCP（本期只看懂，不做练习）

1.64 还给页面加了 WebMCP 支持：现在有些网页会给 AI 助手预留一组可直接调用的「工具」（带名字、说明和参数格式），Playwright 可以把这些工具列出来、逐个调用并断言结果，相当于给「给 AI 用的接口」做接口测试。这一项没有做成练习：它需要被测页面真的注册了工具，还要开浏览器实验开关，你现在的学习阶段没有合适的被测对象。先记住它是什么，等走到 AI 测试那条线（第 4 个月）再回来单独练。
