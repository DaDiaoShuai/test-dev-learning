# test-dev-learning

Frontend to SDET learning repo: Python, test automation and performance testing practice

前端开发转测试开发工程师（SDET / 测试开发）的学习与项目仓库。以 Python 为主力语言，记录从测试基础、接口/UI 自动化，到测试框架搭建与性能测试的完整过程。

## 目标

- 时间：2026 年 10 月下旬 – 2027 年 2 月下旬（3–4 个月）
- 节奏：每周约 8–10 小时（工作日 3 晚各约 1 小时 + 周末约 3 小时整块时间）
- 原则：每个阶段都要有能展示的产出，不只看课；代码和笔记都沉淀在这个仓库

## AI 测试能力线（新增 · 2026-10-23 补入）

按 2026 年公开的测试开发面试能力信息整理：多家大厂的测开岗位已把 AI 应用测试列为能力项，包括大模型输出评测（LLM-as-a-Judge）、RAG 评测集、AI Agent 测试，以及用 AI 辅助生成用例与定位缺陷。这不是新增一门课，而是给每个月加一条并行线，验收点都可打勾：

**第 1 个月：知道考什么 + 会设计评测集**
- [ ] 能用自己的话说清：为什么大模型的回答不能用 `实际 == 预期` 做精确断言，要改用「评测集 + 评分尺度」
- [ ] 完成 01 目录的 [LLM-as-a-Judge 评测集设计练习](01-python-basics/llm-as-judge-exercise.md)（可选加餐）：6 条用例的人工评分与判官评分都跑完，一致率和分歧原因有记录
- [ ] 能给一个没见过的新问题，现场补写出参考要点和 2 / 1 / 0 三档的判定描述

**第 2 个月：把评测跑成自动化**
- [ ] 在接口自动化项目里加一组评测用例：批量调用问答接口、保存每次的回答与得分，跑完能输出达标率（达标条数 ÷ 总条数）
- [ ] 评测集扩到至少 20 条且每条都有参考要点；改一版提示词后，能用同一评测集对比出前后的分数变化
- [ ] 能列出 AI 对话界面的测试点清单（流式输出中断、超时、空回答、应拒答的问题、上下文追问）且每点至少写 1 条用例

**第 3 个月：接入框架与回归 + 性能视角**
- [ ] 评测集接入框架 / CI：每次变更自动跑评测，报告里能看到总分和不达标用例列表
- [ ] 做过一次版本回归对比：同一评测集跑两个版本，结论写清哪版更好、依据是哪几条
- [ ] 用 Locust 对一个问答接口做小并发压测，报告里写清平均延迟、P95 延迟、错误率三个数分别是什么含义

**第 4 个月：面试能讲清**
- [ ] 能在 3 分钟内讲完自己的评测实践：评测集怎么建、尺度怎么定、判官偏差怎么处理
- [ ] 能说清 RAG 评测至少看两个维度（如检索是否命中、回答是否忠实于资料），并各举一个不达标的例子
- [ ] 能说清 Agent 测试与普通接口测试的 3 个不同点（如工具调用轨迹、任务完成率、多步状态）
- [ ] 能说出 LLM-as-a-Judge 的两个已知偏差，并各给出一个缓解办法

## 目录结构

- `01-python-basics/` — Python 核心：数据类型、函数、面向对象、异常、文件与日志、虚拟环境
- `02-test-fundamentals/` — 测试基础与后端基础：用例设计、缺陷生命周期、HTTP/REST、SQL、Linux
- `03-api-automation/` — 接口自动化：Requests + PyTest、参数化、数据驱动、Allure 报告
- `04-ui-automation/` — UI 自动化：Playwright（Python）+ 页面对象模式（POM）
- `05-test-framework/` — 框架合成：统一配置/日志/报告、GitHub Actions、Docker 基础
- `06-performance-testing/` — 性能测试：性能指标与场景设计、JMeter、Locust 与性能报告
- `07-resume-and-interviews/` — 简历提纲与面试复盘（只放脱敏内容，不放个人信息）

## 技术栈

- 语言：Python（主力），JavaScript / TypeScript 为前端背景加分项
- 接口测试：Requests、PyTest、Allure
- UI 测试：Playwright、Selenium（了解）
- 性能测试：JMeter、Locust
- AI 测试：LLM-as-a-Judge 评测、RAG 评测集、AI Agent 测试基础
- 工程化：Git、GitHub Actions、Docker、SQL、Linux
